# ゲーム開始・OBS用観戦開始 仕様書

## 1. 目的と対象範囲

本書は「chopanとチン経衰弱」における、次の2つの開始フローを定義する。

1. ホストがルームを作成し、ゲームを開始するまで
2. ホストがOBS用URLを発行し、OBS画面が観戦を開始するまで

盤面・得点・ターン・演出・効果音の更新には、既存のSocket.IO同期を使用する。

## 2. 用語

| 用語 | 定義 |
| --- | --- |
| ホスト | 現在の`hostSocketId`と一致するプレイヤー。ゲーム開始と観戦URLの取得権限を持つ |
| 通常参加者 | 4桁のルームコードでゲームへ参加するプレイヤー |
| 観戦者 | 観戦専用キーで認証され、読み取り専用でゲーム状態を受信する接続 |
| OBS画面 | `/obs/:roomId?key=:watchKey`で開く、配信用の読み取り専用画面 |
| ルームコード | 通常参加に使用する4桁の数字 |
| 観戦専用キー | ルーム作成時にサーバーが生成する32バイト（256-bit）のランダム値。Base64URL形式では43文字 |

## 3. ゲーム開始仕様

### 3.1 事前条件

- ホストを含む接続中プレイヤーが2人以上、4人以下であること。
- ルーム状態が`waiting`であること。
- 開始要求を送るSocketが現在のホストであること。
- 観戦者はプレイヤー人数に含めない。

### 3.2 利用者の操作

1. ホストはトップ画面で名前を入力し、「ルームを作る」を押す。
2. サーバーは4桁のルームコードと観戦専用キーを生成する。
3. 通常参加者は名前と4桁のルームコードを入力して参加する。
4. 接続中プレイヤーが2人以上になると、ホストの「ゲームをはじめる」ボタンが有効になる。
5. ホストがボタンを押すと、開始要求を1回送信し、クライアントは二重送信防止のため直ちにボタンを隠す。

### 3.3 サーバー処理

`startGame`受信時、サーバーは次の順に検証する。

1. 送信元がルームのプレイヤーであること。
2. 送信元が現在のホストであること。
3. ルーム状態が`waiting`であること。
4. 接続中プレイヤーが2人以上であること。

検証成功後、ゲーム開始前の順番決めへ遷移する。

- ルーム状態を`orderSelection`へ変更する。
- 接続中プレイヤー数と同じ枚数の順番決めカードを生成する。
- 数字は1から人数分までとし、最大値のカードをJOKERとして扱う。
- 選択時間は10秒とする。
- 全員が選択した場合は、その時点で選択を終了する。
- 10秒以内に選択しなかったプレイヤーには、未選択カードをサーバーが自動割り当てする。
- JOKERを最優先とし、その後は数字の降順でプレイ順を決定する。
- 結果を3.5秒表示してから、ルーム状態を`playing`へ変更する。
- 34枚のカードとカード配置をサーバーで生成し、最初のプレイヤーを現在ターンに設定する。

### 3.4 Socket.IOイベント

| 方向 | イベント | 用途 |
| --- | --- | --- |
| Client → Server | `createRoom` | ルーム作成 |
| Server → Host | `roomCreated` | 公開ゲーム状態と再接続用トークンを返す |
| Server → Host | `hostWatchAccess` | ホストだけに観戦専用キーを返す |
| Client → Server | `joinRoom` | 通常参加者の入室 |
| Client → Server | `startGame` | ホストによるゲーム開始要求 |
| Server → Room/Watch | `orderSelectionStarted` | 順番決め開始 |
| Client → Server | `chooseOrderCard` | プレイヤーの順番決めカード選択 |
| Server → Room/Watch | `orderCardChosen` | 選択状況の同期 |
| Server → Room/Watch | `orderRevealed` | 決定したプレイ順の同期 |
| Server → Room/Watch | `gameStarted` | 盤面生成完了とゲーム開始 |

### 3.5 開始拒否条件

| 条件 | 表示メッセージ |
| --- | --- |
| プレイヤーとして未参加 | ルームに参加していません |
| ホスト以外が開始 | 開始できるのはルーム作成者だけです |
| すでに開始済み | ゲームはすでに開始されています |
| 接続中プレイヤーが2人未満 | 2人以上で開始できます |

## 4. OBS用観戦開始仕様

### 4.1 OBS用URLの生成と表示

- 観戦専用キーはルーム作成時にサーバー側で生成する。
- 観戦専用キーは通常の公開ゲーム状態に含めない。
- サーバーは`hostWatchAccess`を現在のホストのSocketだけへ送信する。
- 「OBS用URLをコピー」ボタンは、ホストの待機画面またはゲーム画面だけに表示する。
- 通常参加者、観戦者、OBS画面には、観戦専用キーやコピー用ボタンを表示しない。
- コピーするURLは相対URLではなく、オリジンを含む完全なURLとする。

```text
https://example.com/obs/4821?key=xxxxxxxx
```

### 4.2 OBSでの開始手順

1. ホストが待機画面またはゲーム画面で「OBS用URLをコピー」を押す。
2. OBSでブラウザソースを作成し、コピーした完全なURLを指定する。
3. 推奨表示サイズを1920×1080に設定する。
4. OBSのブラウザソースが`/obs/:roomId`を読み込む。
5. クライアントはURLから4桁のルームコードと`key`を取得する。
6. Socket.IO接続後、`joinWatch`で`roomId`と`key`をサーバーへ送信する。
7. 認証成功時、サーバーは観戦用Socketルームへ接続を追加し、`watchJoined`で現在状態を返す。
8. 以降はプレイヤーと同じ盤面・得点・ターン・演出イベントを読み取り専用で受信する。

### 4.3 認証仕様

- サーバーは次のすべてを満たす場合のみOBS観戦を許可する。
  - `roomId`が4桁の数字である。
  - 対象ルームが存在する。
  - 送信された`key`がルームの観戦専用キーと完全一致する。
- キー比較にはサーバー側のタイミングセーフ比較を使用する。
- ルーム不在、キー欠落、キー不一致を外部から判別できないよう、失敗メッセージは「観戦URLが無効です」に統一する。
- 無効時は盤面、参加者、得点、ターンなどのゲーム情報を表示しない。

### 4.4 読み取り専用制御

OBS接続はプレイヤー配列へ追加せず、最大4人の人数判定にも含めない。

OBS接続から送られた次の操作は成立させない。

- ルーム作成・通常参加
- ゲーム開始
- 順番決めカードの選択
- カードをめくる操作
- 再戦投票
- 待機画面への復帰

OBS画面のカード要素にも操作イベントを付与せず、CSSでもポインター操作を無効化する。

### 4.5 同期対象イベント

認証済みOBS接続は、以下のイベントを観戦用Socketルーム経由で受信する。

- `roomUpdated`
- `orderSelectionStarted`
- `orderCardChosen`
- `orderRevealed`
- `gameStarted`
- `cardFlipped`
- `pairMatched`
- `pairFailed`
- `turnChanged`
- `jokerActivated`
- `gameEnded`

ルーム終了時は`watchUnavailable`を受信し、「このルームは終了しました」と表示する。

### 4.6 OBS表示・音声

- OBS画面ではトップへ戻る導線、ブランド表示、ルーム番号など配信に不要な要素を非表示にする。
- 盤面、得点、現在ターン、残りペア、演出、結果を表示する。
- 効果音とターン読み上げは観戦画面用の音設定に従う。
- ブラウザの自動再生制限により、音声開始に画面上の操作が必要になる場合がある。

## 5. 状態遷移

```text
ルーム未作成
  └─ createRoom → waiting
       ├─ joinRoom → waiting（参加者追加）
       └─ startGame → orderSelection
            ├─ 全員選択
            └─ 10秒経過（未選択を自動割当）
                 └─ orderResult
                      └─ 3.5秒経過 → playing
```

OBS接続は上記のゲーム状態を変更せず、認証成功後に現在状態から同期を開始する。

```text
/obs/:roomId?key=:watchKey
  └─ Socket.IO接続
       └─ joinWatch(roomId, key)
            ├─ 認証成功 → watchJoined → 継続同期
            └─ 認証失敗 → watchUnavailable（ゲーム情報は非表示）
```

## 6. 受け入れ条件

- ホストかつ接続中プレイヤー2人以上の場合だけゲームを開始できる。
- ゲーム開始後、順番決めと盤面開始が全プレイヤー・観戦者へ同期される。
- ルームごとに十分ランダムで異なる観戦専用キーが生成される。
- 4桁のルームコードだけではOBS画面のゲーム情報を取得できない。
- 正しいOBS用URLでは途中参加でも現在の盤面を取得できる。
- OBS接続はプレイヤー人数に含まれず、すべてのゲーム操作が拒否される。
- 観戦専用キーとコピー用ボタンはホスト以外へ送信・表示されない。
- 無効なURLでは「観戦URLが無効です」以外のゲーム情報を表示しない。
- ホスト再接続後も、ホストだけがOBS用URLを再取得できる。
